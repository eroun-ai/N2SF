Clef 개인정보 판별 설계

온프레미스 환경(24GB GPU 1장)에서 문서 속 개인정보의 존재 여부, 엔티티 종류, 차단 여부를 판정하는 구조입니다. 대상 법역은 한국, 일본, 미국, 사우디아라비아이며, 판정 경로에는 디코더를 두지 않습니다.

역할 분리

Clef는 텍스트 구간을 출력하지 못하므로, 위치·의미·법적 결론을 서로 다른 구성요소가 담당합니다.

위치 찾기규칙 탐지기 · 인코더 태거

정규식·검증식으로 정형 번호를, Clef로 학습한 소형 인코더로 서술형 개인정보의 구간을 찾습니다.

의미 판정Clef-flash 9B

후보가 실제 개인정보인지, 어떤 종류인지, 예시값인지를 확률로 판정합니다.

법적 결론정책 엔진 (규칙 테이블)

법역·적용 지점·엔티티·규모를 조합해 조치와 근거 조항을 결정합니다. 법 개정 시 테이블만 수정합니다.

판정 경로의 모든 모델은 순전파 1회로 결과를 반환합니다. 자기회귀 디코더(System 2)는 토큰을 하나씩 생성하므로 판정 경로에서 제외했습니다.

전체 흐름

Clef 요청 구조

요청은 [문서 카드] + [창 본문] + [질문] 순서로 고정합니다. 같은 문서의 창들은 문서 카드 부분의 연산 결과를 공유하고, 한 묶음으로 동시에 처리됩니다.

v0.1 대비 호출 수

10쪽 인사 문서(약 5,000토큰) 기준 추정입니다. 막대 길이는 Clef 호출 횟수에 비례합니다.

불확실 건 처리

불확실성은 이미 계산된 값으로 측정하고, 상위 모델로 넘기지 않습니다. 해석이 갈려도 조치가 같으면 결론에 영향이 없으므로 그대로 처리합니다.

학습과 환류

반복 호출이 많은 작업(토큰 단위 정답 표시, 섭동 검사)은 오프라인으로 분리합니다. 판정 경로에는 학습 결과만 배포합니다.

GPU 배분 (24GB 1장)

막대 길이는 메모리 용량에 비례합니다. 범위로 제시한 값은 중간값으로 그렸으며 실측 전 추정치입니다.

차단 정책 (기본값 예시)

법역이 여러 개이면 가장 엄격한 규칙을 적용합니다. 예를 들어 한국 기관 문서에 일본인 직원의 마이넘버가 있으면, 한국 규칙과 일본 번호법 규칙 중 엄격한 쪽을 적용합니다.

엔티티 코드 (주요 항목)

코드 형식은 {법역}.{대분류}.{세부 유형}입니다. Clef에는 대분류(약 10개)를 먼저 묻고, 세부 유형은 추정 법역에 맞춘 5~20개 선택지로 묻습니다. 이렇게 하면 선택지 255개 제한 안에서 유형 간 혼동을 줄일 수 있습니다.
